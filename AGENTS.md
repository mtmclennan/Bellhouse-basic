Service Area Page Standards (Bellhouse)

Structure:

- Hero
- Local intro
- Core services
- Why choose Bellhouse
- Who it’s for
- FAQ
- CTA

Rules:

- Each section must have one clear purpose
- Do not repeat the same value proposition across sections
- Do not create extra sections to solve weak content
- Reuse existing components before creating new ones
- Maintain SASS-based design system

Local SEO:

- Each page must include real local context (terrain, access, job types)
- Avoid generic "we serve [city]" language
- Do not create doorway-style pages with swapped city names

Conversion:

- CTA must be clear, direct, and practical
- Avoid vague or soft language
- Include one strong CTA (mid-page optional if justified)

Content:

- Remove placeholder or meta explanations about the page itself
- Keep tone practical and contractor-focused
- Avoid generic marketing language

Trust:

- Include regional credibility where appropriate (e.g., since 1982)
- Do not imply physical offices in every city

FAQ:

- Must answer real customer questions
- Must include useful, complete answers (not just headings)
- Should support both SEO and conversion

Internal Linking:

- Link to core services naturally
- Use descriptive anchor text
- Avoid overlinking

Consistency:

- All service-area pages must follow the same structure
- Each page must still feel locally unique
